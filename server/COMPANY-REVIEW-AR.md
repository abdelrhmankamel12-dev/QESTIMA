# QESTIMA — نسخة مراجعة لسيرفر الشركة

هذه نسخة تطوير، وليست إصدار Windows جاهزًا للاستخدام الجماعي. لا يوجد تفعيل أو ترخيص أو اشتراك في مسار `company-server`.

## ما تم تنفيذه

- إعداد مسؤول الشركة مرة واحدة من جهاز السيرفر، برمز عشوائي ينتهي بعد 15 دقيقة. لا ينشئ المستخدم دوره بنفسه.
- كلمات مرور مجزأة باستخدام scrypt، وجلسات محفوظة على السيرفر بمعرّفات عشوائية مخزنة بشكل مجزأ، مع انتهاء بعد الخمول وإلغاء الجلسات عند تعديل الصلاحيات.
- تحقق Authenticator إلزامي لمن يملك الصلاحيات الإدارية أو التجارية. مفاتيح التحقق مشفرة على السيرفر باستخدام AES-GCM. التحقق وفق RFC 6238 مع منع إعادة استخدام الرمز واختبارات المتجهات المنشورة في https://www.rfc-editor.org/rfc/rfc6238 .
- رموز لاستعادة عامل التحقق عند فقد الهاتف، تتطلب كلمة المرور الحالية، وتُلغي الجلسات وعوامل التحقق السابقة. نسيان كلمة المرور نفسها يحتاج مسارًا إداريًا لم يكتمل بعد.
- صلاحيات حسب الدور مع استثناءات سماح/منع، ومشروعات مسندة، وانتهاء اختياري للاستثناء. بعد انتهاء الاستثناء يعود الإذن إلى الدور، وليس بالضرورة إلى المنع.
- منع تعطيل آخر مسؤول نشط لديه تحقق ثنائي وصلاحية إدارة دائمة.
- واجهة عربية لإدارة الحسابات والصلاحيات والمشاريع وسجل العمليات.
- نموذج بيانات تجريبي على السيرفر يفصل Dry Cost عن بيانات المصاريف والربح. لا يرسل القسم التجاري للمُسعّر في القراءة أو التصدير أو ردود تعارض الإصدارات.
- متابعة تقدم المشاريع المسجلة على هذا السيرفر، كل 30 ثانية عند فتح صفحة المتابعة، مع إظهار وقت آخر اتصال ناجح.
- تغيير بيانات مشروع معتمد يُلغي اعتماده. الحفظ يحتاج رقم الإصدار لمنع استبدال تحديث أحدث.
- تبسيط الشريط العلوي في تطبيق Windows إلى HOME — TENDER AI — ESTIMATION — DRAWING — SUPPLIER — REPORTS. دمج أوامر File في HOME وأوامر Dimensions في DRAWING، وإصلاح فقدان مساحات العمل ومواضع التمرير عند التنقل.

## التشغيل للمراجعة التقنية

يتطلب هذا المصدر Node.js 24. حزمة تثبيت السيرفر مع البيئة المدمجة وخدمة Windows لم تُجهّز بعد.

```bash
npm run company-server
```

افتح `http://127.0.0.1:47610` من جهاز السيرفر. اقرأ رمز الإعداد من `company-data/first-setup.txt` وأكمل إنشاء الحساب، ثم اربط Authenticator واحفظ رموز الاسترداد خارج البرنامج. الرمز الموجود في الملف لا يعمل بعد اكتمال الإعداد، حتى إذا بقي الملف موجودًا.

متغيرات الإعداد: `QESTIMA_COMPANY_DATA` لمجلد البيانات، `QESTIMA_COMPANY_HOST` للعنوان، `QESTIMA_COMPANY_PORT` للمنفذ، `QESTIMA_TLS_CERT` و`QESTIMA_TLS_KEY` لشهادة ومفتاح HTTPS. الاستماع على عنوان شبكة بدل localhost يتطلب HTTPS. يجب أن تكون شهادة الشركة موثوقة على أجهزة الموظفين؛ لا تعطّل التحقق من الشهادة.

يحمي مسؤول IT مجلد البيانات ومفتاح السيرفر بصلاحيات نظام التشغيل؛ إعداد mode=0600 لا يغني عن ACL في Windows. نسخة SQLite في هذا المسار غير مشفرة كملف كامل؛ يلزم حماية قرص السيرفر والنسخ الاحتياطية. يجب حفظ قاعدة البيانات ومفتاح السيرفر معًا في النسخ الاحتياطية، وعدم أخذ نسخة من ملف SQLite وحده أثناء تشغيله دون إجراء نسخ متسق.

لا تشغّل `npm run central-server` لهذا الاستخدام: ذلك هو المسار التجاري القديم الموجود للتوافق والاختبارات، ولم يتحول إلى السيرفر الداخلي الجديد.

## ما لم يكتمل — شرط قبل إصدار نسخة شركات

1. ربط Windows بالسيرفر الجديد، فصل الوضع الفردي عن وضع الشركة، ومنع تنزيل المشاريع التجارية كاملة إلى أجهزة المُسعّرين. الصلاحيات الجديدة لا تحمي النسخة المحلية المستقلة بعد.
2. ترحيل نموذج مشروع QESTIMA الكامل: الكميات الثلاث، الموارد والتحليلات، قياسات الرسومات ومرفقاتها، الموردون، التقارير، وتاريخ الإصدارات. نموذج السيرفر الحالي يختبر بنودًا بتكلفة مباشرة وبيانات تجارية منفصلة فقط.
3. شجرة مشروع سياقية، تابات فعلية لكل ملف ورسم ومشروع مع حفظ التكبير والفلاتر والتحديد، ولوحات قابلة لتغيير الحجم. الإصلاح الحالي يحتفظ بتابات صفحات العمل؛ ليست بعد تابات ملفات مستقلة.
4. لصق متعدد الخلايا وتعبئة لأسفل وتثبيت أعمدة وتراجع تجميعي موثوق، ومعاينة أثر تغيير الكميات والأسعار قبل الاعتماد.
5. استرداد كلمة المرور بواسطة مسؤول مخوّل، تغيير كلمة المرور الشخصي، وربط Active Directory إن طُلب.
6. تنصيب السيرفر كخدمة Windows مع النسخ الاحتياطي والاستعادة، واختبار على جهاز سيرفر وعميلين داخل شبكة الشركة.
7. اختبار مشروع MEP كامل بمستنداته وحصره وتحليلاته وعروض الموردين وتقرير نهائي مطابق للحسابات المرجعية.

لا يوجد في هذه النسخة ادعاء بمزامنة تلقائية للمشاريع الحالية أو اكتمال دعم DWG/Revit أو اختبار Windows جديد. يجب مراجعة الواجهة قبل إصدار المثبّت كما طلب المستخدم.

## إضافة ملف TENDER AI الأخير

تم إضافة تاب TENDER AI وقائمة مراجعة قبل اعتماد المستندات، مع تصنيف محلي من اسم الملف دون نسب ثقة مصطنعة. يستطيع المهندس تصحيح التصنيف واعتماد هوية المستند وإصداره واختيار الإصدار الذي يحل محله صراحة. ملفات المراجعة تدخل حزمة المشروع. لا يوجد حاليًا استخراج عقد أو مواصفات باستخدام نموذج لغوي أو فحص تلقائي شامل بين المستندات. لا تُرسل الملفات لخدمة خارجية.

وافق المستخدم صراحة على رفع الكود إلى مستودع QESTIMA وتشغيل اختبارات المراجعة. نجحت 67 حالة اختبار واختبارات واجهة المتصفح لإدارة الشركة والتفاعل مع جدول التسعير في GitHub Actions run 34390094966 على commit 3550c20. لم يُنفذ اختبار Windows لهذا التحديث.

إصلاح لاحق للمراجعة: استيراد CAD يمر بقائمة مراجعة المستندات قبل اعتماده، مع إعادة فحص المشروع والصلاحية بعد اختيار الملف. أُضيف اختبار متصفح لاعتماد مستند عبر نافذة المراجعة.
